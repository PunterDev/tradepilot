# SOC 2 Technical Security Evidence

Assessment date: 2026-08-31

This document records repository-verifiable technical controls added during the SOC 2 remediation pass. It does not claim SOC 2 compliance and does not replace management approvals, provider screenshots, alert test records, access reviews, or auditor evidence.

## Distributed Rate Limiting

Production now has a database-backed rate-limit store:

- Implementation: `backend/src/main/java/com/tradepilot/security/DatabaseRateLimiter.java`
- Interceptor: `backend/src/main/java/com/tradepilot/security/RateLimitInterceptor.java`
- Production migration: `backend/src/main/resources/db/migration/V006__distributed_rate_limit_windows.sql`
- Verification SQL: `backend/db/verify_production_schema.sql`
- Tests: `backend/src/test/java/com/tradepilot/security/DatabaseRateLimiterTests.java`, `FlywayProductionSchemaTests.java`, `FlywayPostgresBaselineIntegrationTest.java`

The PostgreSQL table `rate_limit_windows` is the authoritative shared state. Each request updates one key with `insert ... on conflict ... returning`, so multiple Render instances share one limiter window instead of relying on JVM-local memory. Local/test environments still use `InMemoryRateLimiter` by default for developer ergonomics.

Production startup validation requires:

- `RATE_LIMIT_STORE=database`

If production is configured with the in-memory limiter, application startup fails.

Forwarded client IPs are not trusted by default. `X-Forwarded-For` is only used when `RATE_LIMIT_TRUST_FORWARDED_HEADERS=true` and the immediate proxy address is loopback, private, or listed in `RATE_LIMIT_TRUSTED_PROXIES`; otherwise the servlet remote address is used. This prevents direct clients from bypassing anonymous limits by spoofing `X-Forwarded-For`.

## Admin Access Protection

Application admin routes already require the `ADMIN` role through Spring Security. Production startup validation now also requires an explicit admin access protection declaration:

- `APP_ADMIN_ACCESS_PROTECTION=external-mfa`
- or `APP_ADMIN_ACCESS_PROTECTION=privileged-access-gateway`

This is an enforceable configuration gate, not proof that the external control is operating. Before Type I readiness, TradePilot must retain evidence that admin access is protected by MFA, SSO, VPN, or another auditor-acceptable privileged access gateway.

## SAST, Dependency, and Secret Scanning

Security scanning CI was added:

- Workflow: `.github/workflows/security-scans.yml`
- Secret scan: Gitleaks
- Dependency scan: OWASP Dependency-Check for Maven with CVSS >= 8 build failure, and `npm audit --audit-level=high`
- SAST: Semgrep Java/TypeScript/JavaScript rules with `--error`

The workflow must be configured as a required check on the production branch/deployment path. Passing workflow logs and any triage tickets become audit evidence.

## Centralized Logging and Alerting

Repository-verifiable controls:

- Request, AI, email, Stripe, cache, slow query, and alert records are persisted by the observability implementation.
- Retention windows are configurable in `application.yml`.
- Critical alert records are generated by `ObservabilityAlertService`.

Still external configuration required:

- Centralized log destination and retention settings.
- Alert routing to an accountable owner.
- A retained alert test proving notification, acknowledgement, and response.

## Frontend Session and XSS Hardening

Frontend auth storage now uses session-scoped storage in production while retaining legacy localStorage read compatibility:

- Implementation: `frontend/src/api/authStorage.ts`
- API client integration: `frontend/src/api/axios.ts`
- Auth persistence integration: `frontend/src/api/authApi.ts`
- Activation redirect auth check: `frontend/src/utils/activationRedirect.ts`

Vercel response headers now include:

- Content Security Policy
- Referrer Policy
- `X-Content-Type-Options: nosniff`
- Permissions Policy
- HSTS

Attribution and non-sensitive user experience preferences remain in localStorage. JWTs are still bearer tokens accessible to frontend JavaScript while a session is active; a future httpOnly cookie or refresh-token redesign would further reduce XSS impact.

## Security Headers

Backend Spring Security also emits:

- `X-Content-Type-Options`
- Referrer Policy
- HSTS on secure requests
- `Permissions-Policy`
- `frame-ancestors 'none'` outside dev/test H2 console mode

Frontend hosting emits the browser-facing CSP and related headers through `frontend/vercel.json`.
